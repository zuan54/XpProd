# XPprod — сайт и комплект публикации

В комплекте находится статический сайт XPprod. Главная страница — `index.html`.

## Важно: выберите площадку публикации

**GitHub можно использовать как место хранения исходников. Но GitHub Pages не лучший основной хостинг для этого сайта:** правила GitHub Pages говорят, что сервис не предназначен для бесплатного хостинга сайта, который продвигает коммерческий бизнес. Кроме того, доступность GitHub Pages из России не гарантируется. Если приоритет — чтобы заказчики в РФ открывали сайт без VPN, разместите файлы на российском хостинге и подключите собственный домен. GitHub останется репозиторием/резервной копией.

Другой вариант — российская облачная платформа с деплоем из GitHub (например, Timeweb Cloud App Platform) либо обычный виртуальный хостинг у провайдера с серверами и доменом, доступными вашей аудитории. Перед оплатой проверьте доступность из нескольких сетей РФ.

## Перед публикацией — обязательно замените домен

Поиск в Google/Яндексе и sitemap нуждаются в постоянном публичном URL. Сейчас домен неизвестен и безопасно не выдумывается. По всему комплекту временно стоит `https://YOUR-DOMAIN.example/`.

1. Купите или используйте ваш домен (желательно короткий и брендовый).
2. В `index.html` замените `https://YOUR-DOMAIN.example/` в canonical, Open Graph и JSON-LD на основной URL, например `https://xpprod.ru/`.
3. В `robots.txt` замените домен в строке `Sitemap:`.
4. В `sitemap.xml` замените значение внутри `<loc>`.
5. Если используете домен через GitHub Pages, создайте настоящий файл `CNAME` (именно без расширения) с одной строкой домена. Для российского хостинга CNAME-файл обычно не нужен.
6. Откройте `index.html` поиском `YOUR-DOMAIN` и убедитесь, что совпадений не осталось.

Не размещайте сайт с `YOUR-DOMAIN.example`: это только заглушка и для индексации не годится.

## Способ A — GitHub как репозиторий + российский хостинг (рекомендую для РФ)

### 1. Создайте репозиторий

1. Войдите на GitHub и нажмите **New repository**.
2. Назовите, например, `xpprod-site`.
3. Выберите **Public** (или Private, если ваш тариф/способ деплоя это допускает) и создайте репозиторий.
4. Загрузите в корень репозитория файлы из этого комплекта: `index.html`, `robots.txt`, `sitemap.xml`, `favicon.svg`, `site.webmanifest`, `.nojekyll`, `README.md`.

Через веб-интерфейс: **Add file → Upload files**, перетащите файлы и нажмите **Commit changes**. Точка в имени `.nojekyll` важна.

### 2. Подключите российский хостинг

Вариант 1 — App Platform, которая подключается к GitHub: выберите репозиторий `xpprod-site`, ветку `main`, тип приложения **Static/Frontend**. Так как сайт уже собран и `index.html` лежит в корне, команда сборки обычно не нужна, а директория публикации — корень репозитория (`.` или `/`, как требует панель). Подключите домен в панели платформы и включите бесплатный SSL.

Вариант 2 — обычный виртуальный хостинг: скачайте файлы из репозитория и загрузите их в корневую публичную папку сайта (часто `public_html`, но проверьте в панели конкретного провайдера). Главный файл должен лежать прямо в корне сайта и называться `index.html`. Подключите домен и активируйте SSL-сертификат.

После публикации проверьте сайт через мобильный интернет МТС/Билайн/Мегафон/Т2 и домашний интернет в РФ. Проверьте не только HTML, но и загрузку `player.vimeo.com`: сайт может открываться, а внешний Vimeo-плеер — нет.

## Способ B — GitHub Pages (только если подходит по условиям GitHub и доступности)

GitHub Pages публикует статические файлы. Для коммерческого сайта XPprod правила GitHub Pages могут быть не подходящими, поэтому сначала проверьте текущие условия сервиса.

1. Загрузите файлы в корень репозитория.
2. Откройте **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**.
4. Выберите branch `main`, folder `/(root)`, затем **Save**.
5. Дождитесь зелёного статуса в **Actions**. GitHub покажет URL вида `https://USERNAME.github.io/REPOSITORY/`.
6. Убедитесь, что относительная страница действительно открывается. Для продвижения лучше собственный домен.
7. Собственный домен добавляется в **Settings → Pages → Custom domain**, затем настраиваются DNS-записи у регистратора, после выдачи сертификата включается **Enforce HTTPS**.

Официальная инструкция: https://docs.github.com/pages/getting-started-with-github-pages

## Видео и доступность в России

Веб-страница сама по себе не переносит видео на ваш хостинг: ролики сейчас встроены с Vimeo. Доступ к сайту и доступ к `vimeo.com`/`player.vimeo.com` — разные вещи. Если Vimeo не открывается у конкретного российского оператора или региона, видео не заработают, даже если сам сайт доступен.

Для гарантированной работы роликов в РФ потребуется отдельное решение для видео: хранение/раздача файлов на выбранном хостинге или российском видеосервисе с embed/API. Учитывайте лицензию, согласия на публикацию и трафик; не вставляйте исходные тяжёлые видео прямо в HTML. Проверяйте воспроизведение с мобильных сетей РФ до запуска рекламы.

## Что нужно для появления в Google и Яндексе

Нельзя гарантировать, что сайт «сразу выйдет» первым по запросам **«видеограф Екатеринбург»** или **«продакшн Екатеринбург»**. Sitemap помогает роботам обнаружить URL, но не гарантирует индексацию и позиции. Нужны время, конкурентный контент, ссылки/упоминания, хороший пользовательский опыт и полные контакты компании.

1. Сначала опубликуйте сайт по финальному HTTPS-домену и проверьте, что он отдаёт `200 OK`, не закрыт паролем и доступен роботам.
2. Проверьте в браузере `https://ВАШ-ДОМЕН/robots.txt` и `https://ВАШ-ДОМЕН/sitemap.xml`.
3. Создайте Google Search Console, добавьте ресурс типа **Domain** и подтвердите домен DNS TXT-записью у регистратора. После этого отправьте sitemap `https://ВАШ-ДОМЕН/sitemap.xml` и используйте **URL Inspection → Request indexing** для главной.
4. Создайте Яндекс Вебмастер, добавьте и подтвердите сайт, отправьте тот же sitemap. Если доступно, добавьте Яндекс Метрику и проверяйте страницы/ошибки обхода.
5. Сделайте реальные уникальные тексты об услугах и проектах: «видеограф в Екатеринбурге», «видеосъёмка для бизнеса», «съёмка Reels», «монтаж видео» — естественно, без повторения ключей в каждом абзаце.
6. Добавьте реальные имя/название, телефон, рабочую почту, точную зону обслуживания, способы связи, кейсы с описанием задачи и результата. Сейчас контакты в макете ведут в Telegram; проверьте, что ссылка `https://t.me/Zuan54` — актуальная. Не публикуйте вымышленные адрес, телефон и отзывы.
7. Создайте/заполните профиль компании в Яндекс Бизнесе и Google Business Profile, если вы соответствуете их требованиям; единообразно укажите название, адрес/зону, телефон, сайт и часы работы.
8. Попросите клиентов/партнёров ссылаться на сайт и получить настоящие отзывы на площадках, где работает ваша аудитория.
9. Через 1–4 недели проверьте индексацию запросами `site:ВАШ-ДОМЕН` и отчётами Search Console/Вебмастера. Сроки могут быть дольше; топ по конкурентному запросу не гарантируется.

## SEO, уже добавленное в `index.html`

- русский `lang`, описательный title/description и локальные формулировки;
- canonical и Open Graph (требуют замены домена; для `og:image` загрузите собственную карточку `og-cover.png` или уберите метатег);
- JSON-LD типа `ProfessionalService` с Екатеринбургом и Telegram;
- `robots.txt`, `sitemap.xml`, favicon и webmanifest.

Schema/ключевые слова не дают автоматического буста. Не добавляйте ложные оценки, точный адрес или телефон. Если не принимаете посетителей в офисе — не указывайте домашний адрес; для бизнес-профиля используйте допустимую зону обслуживания.
